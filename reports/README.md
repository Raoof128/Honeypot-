# Reports Directory

This directory contains threat intelligence reports generated from honeypot data.

## Directory Structure

```
reports/
├── sample_reports/      # Example reports demonstrating output formats
│   ├── sample_iocs.json                 # Example IOC extraction output
│   ├── sample_geo_analysis.json         # Example geographic analysis
│   ├── sample_mitre_analysis.json       # Example MITRE ATT&CK mapping
│   ├── sample_threat_feed.stix.json     # Example STIX 2.1 threat feed
│   └── sample_executive_report.md       # Example weekly executive report
│
├── templates/           # Report templates
│   └── threat_report_template.md        # Template for threat reports
│
├── generated/           # Auto-generated reports (on-demand)
│   └── .gitkeep
│
└── automated/           # Scheduled automated reports (weekly)
    └── .gitkeep
```

## Report Types

### IOC Extraction (`iocs_YYYY-MM-DD.json`)

Generated by: `analysis/ioc_extraction.py`

Contains extracted indicators of compromise:
- IP addresses with threat scores and confidence levels
- Domains and URLs
- File hashes (MD5, SHA256)
- Credentials (username/password pairs)
- Commands executed
- Malware families

**Usage:**
```bash
python3 analysis/ioc_extraction.py --days 7 --output reports/generated/iocs.json
```

### Geographic Analysis (`geo_analysis_YYYY-MM-DD.json`)

Generated by: `analysis/geolocation_mapper.py`

Contains geographic distribution of attacks:
- Attack counts by country and city
- Top ASNs (Autonomous System Numbers)
- Attack corridors
- Heat map coordinates
- Temporal patterns

**Usage:**
```bash
python3 analysis/geolocation_mapper.py --days 7 --output reports/generated/geo_analysis.json
```

### MITRE ATT&CK Mapping (`mitre_analysis_YYYY-MM-DD.json`)

Generated by: `analysis/mitre_attck_mapper.py`

Contains MITRE ATT&CK technique mapping:
- Observed techniques and tactics
- Frequency of each technique
- Attack patterns and kill chains
- Threat actor profiles
- ATT&CK Navigator layer export

**Usage:**
```bash
python3 analysis/mitre_attck_mapper.py --days 7 --output reports/generated/mitre_analysis.json
```

### Threat Feeds

Generated by: `analysis/threat_feed_generator.py`

Available formats:
- **STIX 2.1** (`threat_feed_YYYY-MM-DD.stix.json`)
  - Standard structured threat information format
  - Compatible with MISP, ThreatConnect, Anomali
  - Includes indicators, malware objects, threat actors, relationships

- **JSON** (`threat_feed_YYYY-MM-DD.json`)
  - Human-readable JSON format
  - Easy integration with custom tools
  - Complete IOC data with metadata

- **CSV** (`threat_feed_YYYY-MM-DD.csv`)
  - Spreadsheet-compatible format
  - Suitable for firewall import
  - Simplified IOC list

- **MISP** (via PyMISP)
  - Direct upload to MISP instances
  - Automated event creation
  - TLP marking support

**Usage:**
```bash
python3 analysis/threat_feed_generator.py \
  --days 7 \
  --formats stix,json,csv \
  --output reports/generated/
```

### Executive Reports (`report_YYYY-MM-DD.md`)

Generated by: `scripts/generate_report.sh`

Weekly executive summary reports:
- Attack statistics and trends
- Geographic distribution
- MITRE ATT&CK analysis
- Top IOCs
- Malware analysis
- Recommendations

**Usage:**
```bash
./scripts/generate_report.sh --days 7 --output reports/automated/
```

## Automated Report Generation

Weekly reports are automatically generated via cron job:

```bash
# Every Monday at 9 AM
0 9 * * 1 cd /path/to/honeypot && ./scripts/generate_report.sh --days 7
```

Configure schedule in `.env`:
```bash
REPORT_SCHEDULE=0 9 * * 1
AUTO_REPORT_ENABLED=true
REPORT_OUTPUT_DIR=./reports/automated
```

## Report Retention

Default retention periods (configurable in `.env`):
- Generated reports: 180 days
- Automated reports: 365 days

Cleanup is handled by `scripts/cleanup.sh`:
```bash
./scripts/cleanup.sh --days 180
```

## Integration Examples

### Import STIX to MISP

```python
from pymisp import PyMISP

misp = PyMISP('https://misp.local', api_key, ssl=False)
with open('reports/generated/threat_feed.stix.json') as f:
    misp.import_stix(f.read())
```

### Parse JSON IOCs

```python
import json

with open('reports/generated/iocs.json') as f:
    iocs = json.load(f)

high_threat_ips = [
    ip for ip, data in iocs['ips'].items()
    if data['threat_score'] > 70
]
```

### Block IPs from CSV

```bash
awk -F',' 'NR>1 {print $1}' reports/generated/iocs.csv | while read ip; do
  sudo iptables -A INPUT -s $ip -j DROP
done
```

## Report Quality

Reports include confidence scores to indicate IOC quality:
- **0.9-1.0**: Very High - Multiple confirmations, high activity
- **0.7-0.9**: High - Confirmed malicious activity
- **0.5-0.7**: Medium - Suspicious activity, lower confidence
- **0.3-0.5**: Low - Possibly malicious, requires validation
- **0.0-0.3**: Very Low - Borderline, high false positive risk

Default minimum confidence threshold: 0.1 (configurable in `.env`)

## Report Distribution

Reports can be automatically distributed via:
- **Email** (SMTP configuration in `.env`)
- **Slack** (webhook integration)
- **Discord** (webhook integration)
- **MISP** (automatic event creation)
- **S3** (cloud storage backup)

Configure in `.env`:
```bash
REPORT_EMAIL_RECIPIENTS=security@example.com,soc@example.com
SMTP_SERVER=smtp.example.com
SMTP_PORT=587
```

## Troubleshooting

**No reports generated:**
- Check Python scripts execute successfully
- Verify Elasticsearch connection
- Check disk space in reports directory
- Review script logs for errors

**Empty or minimal reports:**
- Ensure honeypots are receiving attack traffic
- Verify Elasticsearch indices contain data
- Check confidence threshold isn't too high

**Report generation takes too long:**
- Reduce time range (--days parameter)
- Optimize Elasticsearch queries
- Increase Python memory limits

For detailed troubleshooting, see [../docs/TROUBLESHOOTING.md](../docs/TROUBLESHOOTING.md)
